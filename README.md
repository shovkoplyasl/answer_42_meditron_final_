# СМ-Клиника: объединённое приложение

## Запуск за минуту — Windows x64

1. Распакуйте **весь** ZIP в доступную для записи папку. Не запускайте файлы внутри архива.
2. Дважды нажмите **START.cmd**. Устанавливать Python, Node.js и зависимости не требуется.
3. Откроется http://127.0.0.1:8050. Дождитесь завершения запуска в окне консоли.
4. Логин **staff**. Случайный пароль создаётся при первом запуске в **local-data/LOCAL_ACCOUNTS.txt**.
5. Нажмите «Импортировать 89 протоколов» для наполнения стенда либо добавьте свой протокол текстом или файлом DOCX.

Повторный импорт не дублирует эти 89 документов. В архиве нет рабочих баз, паролей и сессий. Базы создаются при первом запуске и сохраняются между запусками. Остановка приложения: Ctrl+C в консоли. При занятом порте: `START.cmd --port 8051`. Не запускайте две копии приложения с одной базой одновременно.

## PostgreSQL

Для запуска с PostgreSQL установите и запустите Docker Desktop, затем нажмите **START_POSTGRES.cmd**. Первый запуск требует интернета для загрузки postgres:16. Скрипт создаёт случайный пароль в .env.postgres, поднимает PostgreSQL на 127.0.0.1:55432 и запускает тот же интерфейс. Сервисные учётные записи приложения хранятся отдельно в local-data/access.sqlite3 в обоих режимах.

Данные PostgreSQL сохраняются в именованном томе Docker. **STOP_POSTGRES.cmd** останавливает контейнер без удаления данных. Остановка окна приложения сама контейнер не останавливает. Не меняйте пароль в .env.postgres после создания тома без соответствующего изменения пароля в PostgreSQL.

Обычный START.cmd использует SQLite через исходный SQLAlchemy. Переключение на PostgreSQL не переносит уже введённые данные: это отдельная база. Автоматический перенос не реализован. Конфигурация PostgreSQL приложена; запуск с PostgreSQL на машине сборки не проверен, поскольку Docker-сервис не запущен.

## Что объединено

- backend — бэкенд из sm-clinic-meditron-FINAL.zip; frontend — интерфейс из sm-clinic-admin (2).zip.
- Один адрес и один сервер: FastAPI раздаёт собранный React и обслуживает запросы к БД.
- Вход с проверкой пароля и сессией, выход, защита изменяющих запросов от подделки, ограничение попыток входа.
- Загрузка текста/DOCX, извлечение признаков и подтверждающих цитат исходным алгоритмом FINAL.
- Список протоколов из БД, поиск по тексту и ключевым словам, фильтры, карточка с результатами анализа.
- Изменение маршрута с причиной и журналом; уведомление с предпросмотром и подавлением повторов; демонстрационная запись, сохраняемая в БД.
- Аналитика по загруженным данным и экспорт текста протокола.

Сохранены оформление и основные компоненты исходного интерфейса. Статические данные подключены к БД. Текущий интерфейс предназначен для сотрудника. Отдельный кабинет пациента здесь не реализован.

## Границы демонстрации

Уведомление сохраняется в БД и показывается в браузере: внешняя доставка push/SMS **не подключена**. Слоты записи демонстрационные, запись фиксируется локально; связи с реальным расписанием клиники и 1С нет. Обратный звонок — сохранённое событие, без отправки оператору. NLP не выдаёт измеренную вероятность, поэтому числовая уверенность не подставляется. В исходной БД нет ФИО и демографии: интерфейс показывает анонимный номер и прочерки. Одна строка таблицы соответствует одному протоколу; один пациент может иметь несколько протоколов.

Сервер слушает только 127.0.0.1. Это локальный стенд, а не подтверждённая готовность к размещению в интернете или эксплуатации с реальными персональными данными.

## Структура и разработка

| Путь | Назначение |
|---|---|
| backend/main.py | Исходные эндпоинты FINAL |
| backend/models.py, schemas.py, database.py | Исходные ORM-модели, структуры данных и подключение |
| backend/medroute, services | Исходный анализ и адаптер его результатов |
| backend/database/schema.sql | Исходная схема; вручную не запускать: содержит DROP и фрагмент Python |
| backend/integration_init.py | Безопасная инициализация CREATE IF NOT EXISTS без DROP |
| backend/integrated.py | Связь интерфейса с исходными эндпоинтами, импорт, маршруты, демонстрация записи |
| backend/integration_access.py | Учётные записи, сессии, защита запросов |
| backend/data | Корпус 89 документов и исходная разметка |
| frontend/src | Используемый исходный код React |
| frontend/dist | Готовый интерфейс, раздаваемый FastAPI |
| runtime, python-deps | Python 3.12 и зависимости для Windows x64 |
| local-data | Создаваемые при запуске базы и локальные реквизиты |
| SOURCE_HASHES.json, CHANGES.json | Контроль изменений относительно двух исходных архивов |
| verification.json | Результаты проверок |
| MANIFEST.sha256.json | Контрольные суммы файлов поставки |

В корне frontend могут оставаться старые Python-файлы и main.tsx исходного архива. Они не являются точкой входа: используются backend/integrated.py и frontend/src. Не запускайте прежние инструкции из вложенного backend/README.md для единого стенда; используйте эту инструкцию.

Для изменения интерфейса нужен Node.js 24: в frontend выполните `npm ci`, затем `npm run build`. Для разработки с обновлением страницы: запустите START.cmd, а затем `npm run dev` в frontend (прокси API настроен на 8050). Авторизация рассчитана на локальное происхождение запроса. Основной проверенный режим — собранный интерфейс на 8050. Воспроизводимая установка Python-зависимостей для разработчиков: requirements-lock.txt; для обычного запуска установка не нужна.

## Проверка

**TEST.cmd** запускает 17 исходных тестов и 25 интеграционных проверок на отдельной временной SQLite. Рабочие данные не очищаются. Исходный conftest с TRUNCATE PostgreSQL не используется. Проверяются вход и выход, защита API, цитаты, маршруты, отрицания, DOCX, импорт 89 документов, уведомления и сохранение записи. Эти тесты не являются измерением качества NLP на независимой выборке.

Сборка фронтенда выполнена. Результаты проверок находятся в verification.json. Оригинальный NLP, модели данных и схема сохранены; точные исправления перечислены в CHANGES.json.
